# 지점 장비 현황 지도 — 설계 문서

작성일: 2026-08-04

## 목적

엑셀(.xlsx) 파일 하나를 선택하면, 지점별 장비 보유/정상/비정상 현황을 무료 지도 위에
표시하는 단일 페이지 웹앱. 비정상 장비가 있는 지점을 한눈에 찾는 것이 목표.

## 범위 밖 (하지 않는 것)

- 로그인, 사용자 관리
- 서버 저장 / 데이터베이스 (엑셀은 브라우저 안에서만 파싱)
- 엑셀 편집, 데이터 수정
- AI(OpenRouter) 활용 — 열 이름 매칭과 좌표 변환 모두 결정적 로직으로 충분하며,
  LLM 좌표 추정은 환각 위험이 있어 오히려 해롭다.

## 입력 데이터

기준 파일: `../주소정보.xlsx` (Sheet1, 헤더 1행 + 데이터)

| 이름 | 주 소 | 장비명 | 보유수량 | 정상수량 | 비정상수량 |
|---|---|---|---|---|---|
| 서초금융센터 | 서울 서초구 사임당로23길 27 | VPN | 10 | 8 | 2 |
| 삼성화재IDC | 서울 영등포구 양평로 76 | VPN | 20 | 20 | 20 |
| 삼성화재본사 | 서울 서초구 서초대로74길 14 | VPN | 20 | 20 | 20 |
| 중앙고객지원센터 | 서울 중구 남대문로9길 40 | VPN | 5 | 5 | 4 |
| 강남리더스 | 서울 강남구 테헤란로 114 | VPN | 10 | 8 | 2 |

### 열 매칭 규칙 (헤더 이름 기반, 순서 무관)

공백 제거 후 부분 문자열 매칭. **`비정상`을 `정상`보다 먼저 검사해야 한다**
(`정상수량`이 `비정상수량`의 부분 문자열이므로 순서를 바꾸면 오매칭).

| 필드 | 매칭 키워드 (우선순위 순) |
|---|---|
| `abnormal` | `비정상`, `불량`, `이상`, `장애` |
| `normal` | `정상`, `양호` |
| `total` | `보유`, `총수량`, `수량` |
| `name` | `지점`, `이름`, `지사`, `사업장`, `센터명` |
| `address` | `주소`, `소재지` |
| `equipment` | `장비`, `설비`, `모델` |

`name`, `address` 두 열을 못 찾으면 에러 메시지를 띄우고 중단한다.
`total`이 없으면 `normal + abnormal`로 계산한다.

## 아키텍처

```
브라우저 (서버 없음)
├─ 파일 선택 → SheetJS 로 파싱 → Row[]
├─ 지점 단위 그룹핑 (키: 지점명 + 주소)  → Branch[] (장비 여러 행 합산)
├─ 지오코딩: 주소 → {lat, lng}
│    └─ Nominatim (OpenStreetMap), 1.1초 간격 순차 요청
│    └─ localStorage 캐시 (키: `geo:<주소>`) → 재업로드 시 즉시
└─ 렌더
     ├─ Leaflet 지도 + CircleMarker (비정상≥1 → 빨강, 그 외 → 파랑)
     ├─ 우측 지점 목록 (shadcn Table) — 클릭 시 해당 마커로 이동
     ├─ 상세 Dialog — 지점명/주소/장비별 표
     └─ 좌표 미확인 지점 목록 (지도에서 누락된 것을 숨기지 않기 위함)
```

## 데이터 모델

```ts
type Equipment = { name: string; total: number; normal: number; abnormal: number }
type Branch = {
  id: string            // `${name}|${address}`
  name: string
  address: string
  equipment: Equipment[]
  total: number         // 장비 합산
  normal: number
  abnormal: number
  lat?: number
  lng?: number
  geoError?: string     // 좌표 못 찾은 이유
}
```

## 색상 규칙

- 지도 마커 / 목록 행: `abnormal >= 1` → 빨강(`#dc2626`), 그 외 → 파랑(`#2563eb`)
- 상세 Dialog: **비정상수량 = 빨강**, **정상수량 = 초록**, 보유수량 = 기본색
  (사용자 확정: 최초 요청의 "정상수량을 빨간색"은 오타로 판단, 확인 후 정정)

## 지오코딩 상세

- 엔드포인트: `https://nominatim.openstreetmap.org/search?format=json&limit=1&q=<주소>`
- Nominatim 이용 정책상 **초당 1건 이하** → 요청 간 1100ms 대기, 순차 처리
- 진행 상태를 `n/총건수 변환 중…` 으로 표시 (긴 대기 중 화면이 멈춘 듯 보이지 않게)
- 실패/무결과 시 `geoError` 기록 후 계속 진행 (전체 중단 금지)
- 성공·실패 모두 `localStorage`에 캐시 → 같은 파일 재업로드 시 네트워크 요청 0건
- 정확도 한계: 도로명 단위로 매칭되어 최대 1~2km 오차 가능. 사용자 승인된 트레이드오프.

## 오류 처리

| 상황 | 처리 |
|---|---|
| xlsx 아닌 파일 | "엑셀(.xlsx) 파일을 선택해 주세요" 안내 |
| 시트가 비어 있음 | "데이터가 없습니다" 안내 |
| 필수 열(지점명/주소) 없음 | 찾은 헤더 목록과 함께 에러 표시 |
| 수량 칸이 빈칸/문자 | 0으로 처리 |
| 지오코딩 실패 | 해당 지점만 "좌표 미확인" 목록으로 |
| 네트워크 전체 차단 | 지오코딩 전부 실패 → 목록은 정상 표시 |

## 검증 (테스트)

`src/lib/parse.test.ts` — Vitest, 순수 함수만 대상:
1. 헤더 매칭: `정상수량` / `비정상수량` 이 서로 뒤바뀌지 않는다 (핵심 회귀 테스트)
2. 열 순서를 섞어도 올바르게 매칭된다
3. 동일 지점의 장비 여러 행이 하나로 합산된다
4. 빈칸/문자 수량이 0으로 처리된다
5. 필수 열 없으면 에러를 던진다

지오코딩·지도 렌더는 외부 의존이므로 자동 테스트 대상에서 제외하고, 실제 파일로
브라우저에서 수동 확인한다.

## 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | Vite + React + TypeScript | 정적 파일 산출 → GitHub Pages 배포 가능 |
| UI | shadcn/ui + Tailwind CSS | 사용자 지정 |
| 지도 | Leaflet + OpenStreetMap 타일 | 무료, API 키 불필요 (사용자 선택) |
| 엑셀 | SheetJS (xlsx) | 브라우저 내 .xlsx 파싱 표준 |
| 배포 | GitHub Pages (`donghunee`) | 무료, gh CLI 이미 인증됨 |

## 배포

1. GitHub 저장소 생성 (public)
2. `vite.config.ts`의 `base`를 `/<repo>/`로 설정
3. GitHub Actions 워크플로로 push 시 자동 빌드 → Pages 배포
4. 최종 URL: `https://donghunee.github.io/<repo>/`
